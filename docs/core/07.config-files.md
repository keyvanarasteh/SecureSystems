# 07 — Konfigürasyon Dosyaları (Dotfiles)

> Projenin kök dizinindeki araç yapılandırma dosyalarının (dotfiles) format yapısı,
> özellikleri ve birbirleriyle ilişkisi.
>
> Yazar: Keyvan Arasteh · İstinye Üniversitesi · 2026

---

## Genel Bakış

"Dotfile" (nokta dosyası) adını `.` ile başlamasından alır. İşletim sistemlerinde
gizli dosya olarak kabul edilir. Her biri farklı bir aracı yapılandırır:

| Dosya                 | Aracı              | Format     | Görevi                          |
| --------------------- | ------------------- | ---------- | ------------------------------- |
| `.gitattributes`      | Git                 | Özel söz dizimi | Satır sonu dönüşümleri, ikili dosya tanımı |
| `.prettierignore`     | Prettier            | Glob kalıpları | Formatlanmaması gereken dosyalar |
| `.shellcheckrc`       | ShellCheck          | `key=value` | Shell script linter ayarları     |
| `.npmrc`              | npm                 | `key=value` | Paket yöneticisi ayarları        |
| `.npmignore`          | npm publish         | Glob kalıpları | Pakete dahil olmayan dosyalar    |
| `.detect-secrets.cfg` | detect-secrets      | INI + YAML  | Secret dedektör eklentileri      |
| `.secrets.baseline`   | detect-secrets      | JSON        | Bilinen secret'ların referansı   |

## 1. `.gitattributes` — Git Dosya Nitelikleri

Git'e dosyaların **nasıl işlenmesi** gerektiğini söyler.

### Format

```
kalıp    nitelik=değer
```

### Temel Kurallar

```gitattributes
# Tüm dosyalarda otomatik satır sonu tespiti
* text=auto

# Metin dosyaları — LF zorla (Windows CRLF sorununu önler)
*.js text eol=lf
*.ts text eol=lf
*.sh text eol=lf

# İkili dosyalar — hiç dönüşüm yapma
*.png binary
*.zip binary

# Diff görünümü iyileştirme
*.md diff=markdown
```

### Neden Gerekli?

| Sorun                          | `.gitattributes` Çözümü              |
| ------------------------------ | ------------------------------------ |
| Windows'ta CRLF, Linux'ta LF  | `text eol=lf` ile tutarlılık sağlar  |
| İkili dosyalarda bozuk diff    | `binary` ile diff'i kapatır          |
| Büyük dosyalar repo'yu şişirir | Git LFS ile entegrasyon desteği      |
| Merge çatışmalarında karmaşa   | Dil bazlı diff stratejisi            |

### LF vs CRLF Nedir?

```
LF   = \n      (Linux, macOS)  — tek karakter
CRLF = \r\n    (Windows)       — iki karakter
```

> Bir ekipte hem Windows hem Linux kullanıcıları varsa `eol=lf` ayarı
> herkesin aynı satır sonunu kullanmasını garanti eder.

## 2. `.prettierignore` — Prettier Dışlama

Prettier kod formatlayıcısının **dokunmaması** gereken dosyaları belirler.

### Format

`.gitignore` ile aynı glob söz dizimini kullanır:

```
dist/               # Klasör dışla
*.md                # Tüm markdown dosyaları
package-lock.json   # Özel dosya
!.env.example       # İstisna (! ile)
```

### Neden Bazı Dosyalar Dışlanır?

| Dosya Türü        | Neden                                              |
| ----------------- | -------------------------------------------------- |
| `dist/`, `build/` | Derleme çıktısı — zaten minified                   |
| `*.lock`          | Paket lock dosyaları — elle düzenlenmez             |
| `*.md`            | Markdown'da boşluklar anlamlıdır, Prettier bozabilir |
| `node_modules/`   | Üçüncü parti kod — bizim formatımız geçersiz        |
| `.env*`           | Format hassas — fazla boşluk sorun yaratır          |

## 3. `.shellcheckrc` — Shell Script Linter

Bash/Shell scriptlerindeki hataları bulan **ShellCheck** linter'ının ayarları.

### Format

```ini
# Yorum satırı
key=value
```

### Desteklenen Ayarlar

```shellcheckrc
# Hedef kabuk
shell=bash

# Kapatılacak uyarılar (virgülle ayrılmış)
disable=SC1091,SC2034

# Dış kaynaklardan yüklenen dosyaları kabul et
external-sources=true
```

### Sık Kapatılan Kurallar

| Kural   | Açıklama                                    | Neden Kapatılır               |
| ------- | ------------------------------------------- | ----------------------------- |
| SC1091  | Kaynak dosya bulunamadı (`source ...`)       | Dinamik dosya yolu kullanılıyor |
| SC2034  | Değişken tanımlanmış ama kullanılmamış       | Ortam değişkeni olarak export edilecek |
| SC2086  | Değişken çift tırnaksız                      | Bilinçli word-splitting yapılıyor |

### ShellCheck Referansı

> **🔗 [shellcheck.net/wiki](https://www.shellcheck.net/wiki/)**

## 4. `.npmrc` — npm Yapılandırması

npm paket yöneticisinin davranışını kontrol eder.

### Format

```ini
# Yorum satırı
key=value
```

### Mevcut Ayarlar

```npmrc
save-exact=true         # Tam sürüm kaydet (^1.2.3 yerine 1.2.3)
package-lock=true       # Lock dosyası oluştur
audit-level=moderate    # Güvenlik denetim seviyesi
fund=false              # "npm fund" mesajlarını gizle
```

### `save-exact=true` Neden Önemli?

```
save-exact=false (varsayılan):  "lodash": "^4.17.21"
save-exact=true:                "lodash": "4.17.21"
```

> `^` prefixi ile npm **uyumlu üst sürüm** kurabilir. Bu bazen beklenmeyen
> hatalara yol açar. `save-exact=true` tam sürümü kilitleyerek
> **tekrarlanabilirlik** sağlar.

## 5. `.npmignore` — npm Publish Dışlama

Paket `npm publish` ile yayınlanırken **dahil edilmeyen** dosyalar.

### Format

`.gitignore` ile aynı glob söz dizimi:

```
src/             # Kaynak kod (sadece derleme çıktısı yayınlanır)
test/            # Testler pakette gereksiz
docs/            # Dokümantasyon pakette gereksiz
Dockerfile*      # Docker dosyaları pakette gereksiz
```

### `.npmignore` vs `.gitignore` Farkı

| Özellik         | `.gitignore`             | `.npmignore`              |
| --------------- | ------------------------ | ------------------------- |
| **Kim okur?**   | Git                      | npm                       |
| **Ne yapar?**   | Repo'dan dışlar          | npm paketinden dışlar     |
| **Varsayılan**  | Yoksa hiçbir şey dışlanmaz | Yoksa `.gitignore` kullanılır |

> **Uyarı:** `.npmignore` **varsa** `.gitignore` artık npm tarafından
> okunmaz. İkisi birbirinden bağımsız çalışır.

## 6. `.detect-secrets.cfg` — Secret Tarama Yapılandırması

`detect-secrets` aracının hangi secret türlerini tarayacağını belirler.

### Format

INI başlığı + YAML benzeri yapı:

```ini
[detect-secrets]
plugins_used:
  - name: AWSKeyDetector
  - name: GitHubTokenDetector
  - name: JwtTokenDetector
  - name: PrivateKeyDetector
  - name: StripeDetector

filters_used:
  - name: is_baseline_file
```

### Desteklenen Dedektörler

| Dedektör                | Ne Tarar                        |
| ----------------------- | ------------------------------- |
| `AWSKeyDetector`        | AWS Access Key / Secret Key     |
| `GitHubTokenDetector`   | GitHub Personal Access Token    |
| `JwtTokenDetector`      | JWT (JSON Web Token)            |
| `PrivateKeyDetector`    | RSA/SSH özel anahtarlar         |
| `StripeDetector`        | Stripe API anahtarları          |
| `SlackDetector`         | Slack webhook URL'leri          |
| `HexHighEntropyString`  | Yüksek entropi hex stringleri   |
| `KeywordDetector`       | `password=`, `secret=` gibi kalıplar |
| `BasicAuthDetector`     | `user:pass@host` kalıpları       |

### Kurulum ve Kullanım

```bash
# Kurulum
pip install detect-secrets

# İlk tarama — baseline oluştur
detect-secrets scan > .secrets.baseline

# Sonraki taramalar — yeni sızıntıları bul
detect-secrets scan --baseline .secrets.baseline

# Git pre-commit hook ile entegrasyon
detect-secrets-hook --baseline .secrets.baseline
```

## 7. `.secrets.baseline` — Secret Baseline

`detect-secrets` tarafından oluşturulan **bilinen secret'lar** referans dosyası.

### Format

```json
{
  "generated_at": "2026-03-17T20:00:00Z",
  "plugins_used": [...],
  "filters_used": [...],
  "results": {},
  "version": "1.5.0"
}
```

### Nasıl Çalışır?

```
1. İlk tarama: detect-secrets scan > .secrets.baseline
   → Mevcut durumu "bilinen" olarak kaydeder

2. Sonraki tarama: detect-secrets scan --baseline .secrets.baseline
   → Sadece YENİ sızıntıları raporlar
   → Baseline'daki "bilinen" olanları atlar

3. CI'da: pre-commit hook olarak çalışır
   → Yeni secret commit edilmesini engeller
```

> `results: {}` boş olması **temiz** demektir — şu anda bilinen sızıntı yok.

## Dosyalar Arası İlişki Diyagramı

```
┌─── Git Araçları ──────────────────────────┐
│ .gitignore       → Git'in izlemediği       │
│ .gitattributes   → Satır sonu, ikili dosya │
└───────────────────────────────────────────┘

┌─── Kod Kalitesi ──────────────────────────┐
│ .prettierignore  → Formatlama dışlama      │
│ .shellcheckrc    → Shell script linting    │
└───────────────────────────────────────────┘

┌─── Paket Yönetimi ────────────────────────┐
│ .npmrc           → npm davranış ayarları   │
│ .npmignore       → Publish dışlama         │
└───────────────────────────────────────────┘

┌─── Güvenlik Tarama ───────────────────────┐
│ .detect-secrets.cfg  → Dedektör listesi    │
│ .secrets.baseline    → Bilinen referans    │
└───────────────────────────────────────────┘
```
