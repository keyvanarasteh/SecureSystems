# 02 — AI Agent Yapılandırma Sistemi

> AI kod asistanlarının (Gemini, Claude, Codex) proje ile nasıl etkileşime
> girdiğini kontrol eden **kurallar**, **workflow'lar** ve **yapılandırma dosyaları**.
>
> Yazar: Keyvan Arasteh · İstinye Üniversitesi · 2026

## Genel Bakış

Projede üç farklı AI agent desteklenir. Her birinin kendi talimat dosyası vardır:

| Dosya        | Agent          | Konum         | Açıklama                                                          |
| ------------ | -------------- | ------------- | ----------------------------------------------------------------- |
| `GEMINI.md`  | Google Gemini  | Proje kökü    | Gemini (Antigravity) agentının uyması gereken proje kuralları.    |
| `CLAUDE.md`  | Anthropic Claude | Proje kökü  | Claude agentının uyması gereken proje kuralları ve bağlam bilgisi. |
| `AGENTS.md`  | OpenAI Codex   | Proje kökü    | Codex agentının uyması gereken kurallar ve mimari bilgiler.       |

Bu dosyalar proje kök dizininde durur ve ilgili agent aktif edildiğinde **otomatik olarak okunur**.

## Klasör Yapısı: `.agents/` vs `.agent/`

```
SecureSystems/
├── .agents/                  # ← Birincil (tercih edilen) agent dizini
│   ├── rules/                #    Kural dosyaları
│   │   ├── code-style.md     #    Örnek: always_on kural
│   │   ├── glob-modu.md      #    Örnek: glob tetiklemeli kural
│   │   └── hata-ayiklama.md  #    Örnek: model_decision kural
│   └── workflows/            #    Workflow dosyaları
│       └── wf1.md            #    Örnek: /wf1 komutuyla çağrılan workflow
│
├── .agent/                   # ← Eski (legacy) agent dizini — geriye uyumluluk
│   └── .gitkeep
```

### Fark Nedir?

| Özellik           | `.agents/`                             | `.agent/`                                |
| ------------------ | -------------------------------------- | ---------------------------------------- |
| **Durum**          | ✅ Birincil, aktif dizin               | ⚠️ Legacy, geriye uyumluluk için korunur |
| **Kullanım**       | Kurallar ve workflow'lar burada tanımlanır | Eski projelerde hâlâ okunabilir          |
| **Öneri**          | **Tüm yeni kurallar buraya yazılmalı** | Yeni dosya eklemeyin                     |
| **Alt dizinler**   | `rules/`, `workflows/`                | Genellikle boştur                        |

> **Not:** Antigravity (Gemini) artık varsayılan olarak `.agents/rules` kullanır,
> ancak `.agent/rules` da geriye dönük desteklenir. Yeni kuralları her zaman
> `.agents/rules` altına koyun.

## Global Yapılandırma: `~/.gemini/GEMINI.md`

Gemini agentının **tüm projeler** için geçerli olan global kuralları
`~/.gemini/GEMINI.md` dosyasında tanımlanır.

```
~/.gemini/
└── GEMINI.md    # Global kurallar — her workspace'te geçerli
```

| Özellik       | Detay                                                        |
| ------------- | ------------------------------------------------------------ |
| **Konum**     | `~/.gemini/GEMINI.md` (kullanıcının home dizini altında)     |
| **Kapsam**    | Tüm çalışma alanlarında geçerli                              |
| **Kullanım**  | Kişisel tercihler, genel kodlama stili, dil tercihi vb.      |
| **Limit**     | 12.000 karakter                                              |

### Ne Yazılmalı?

- Tüm projelerde uygulanmasını istediğiniz **genel kurallar**
- Kişisel kod stili tercihleri (örn. "Türkçe yorum yaz", "her zaman TypeScript strict mod kullan")
- Sık kullandığınız komut kısayolları

### Örnek

```markdown
# Global Kurallar

- Kod yorumlarını Türkçe yaz.
- Her fonksiyona JSDoc/TSDoc ekle.
- Commit mesajları Conventional Commits formatında olsun.
- Test coverage %70'in altına düşmesin.
```

## Rules (Kurallar) Sistemi

Kurallar, agentın davranışını yönlendiren **Markdown dosyalarıdır**. Her kural
dosyasının başında YAML frontmatter bulunur.

### Kural Dosyası Formatı

```markdown
---
trigger: always_on | model_decision | glob | manual
description: Kuralın ne zaman uygulanacağının kısa açıklaması (maks. 250 karakter)
---

Kuralın içeriği buraya yazılır.
Maksimum 12.000 karakter.
```

### Tetikleme (Trigger) Modları

| Mod              | Nasıl Çalışır                                                                    | Ne Zaman Kullanılır                                |
| ---------------- | -------------------------------------------------------------------------------- | -------------------------------------------------- |
| `always_on`      | Kural **her zaman** uygulanır, her istekte aktiftir.                             | Kod stili, güvenlik kuralları gibi sabit kurallar   |
| `model_decision` | Agent, `description` alanındaki açıklamaya bakarak kuralı **kendisi uygulayıp uygulamayacağına** karar verir. | Duruma göre değişen kurallar (hata ayıklama vb.)   |
| `glob`           | Belirtilen dosya kalıbına uyan dosyalar açıkken kural aktif olur (örn. `*.ts`, `src/**/*.js`). | Dosya tipine özel kurallar                          |
| `manual`         | Kural sadece kullanıcı `@kural-adı` ile bahsettiğinde aktif olur.               | Nadir kullanılan veya duruma özel kurallar          |

### Limitler

| Alan            | Limit             |
| --------------- | ----------------- |
| `description`   | **250** karakter  |
| İçerik (body)   | **12.000** karakter |

### Mevcut Projede Örnek Kurallar

#### 1. `code-style.md` — Always On

```markdown
---
trigger: always_on
---

Kural ornek 1
```

> Her istekte otomatik uygulanır. Kod stili, formatlama, isimlendirme kuralları
> gibi **değişmez** standartları burada tanımlayın.

#### 2. `hata-ayiklama.md` — Model Decision

```markdown
---
trigger: model_decision
description: Every Coding Place
---

Tüm mantıksal ve hata oluşturabilecek kod parçaları hata ayıklama
yöntemleriyle kapsanmalı ve log'ları görmeli...
```

> Agent, kodla ilgili bir iş yaparken bu kuralı **kendi kararıyla** uygular.
> `description` alanı agentın karar vermesine yardımcı olur.

#### 3. `glob-modu.md` — Glob Pattern

```markdown
---
trigger: glob
---

Maksimum Glob Pattern 250 karakter Destekliyor
12000 karakter.
```

> Belirli dosya tiplerinde çalışırken aktif olur.
> Örnek kalıplar: `*.ts`, `*.py`, `src/**/*.rs`, `test/**/*.test.js`

## Workflows (İş Akışları)

Workflow'lar, agentı **adım adım** bir süreçten geçiren tekrarlanabilir
talimat dosyalarıdır. `/workflow-adi` komutuyla çağrılır.

### Workflow Dosya Formatı

```markdown
---
description: Kısa açıklama (maks. 250 karakter)
---

1. İlk adım talimatları
2. İkinci adım talimatları
3. Üçüncü adım talimatları
```

### Konum

```
.agents/workflows/
└── wf1.md           # /wf1 komutuyla çağrılır
```

### Limitler

| Alan          | Limit             |
| ------------- | ----------------- |
| `description` | **250** karakter  |
| İçerik (body) | **12.000** karakter |

### Kullanım Senaryoları

- **Deploy süreci:** "Docker build → test → push → deploy" adımları
- **PR review süreci:** "Kodu oku → testleri çalıştır → yorum yaz"
- **Ders tekrarı:** Öğrencilerin derste gösterilen adımları evde tekrar etmesi
- **Güvenlik taraması:** "Bağımlılık taraması → secret taraması → SAST → rapor"

### Workflow Zincirleme

Bir workflow içinden başka bir workflow çağrılabilir:

```markdown
---
description: Tam deploy süreci
---

1. Kodu kontrol et
2. /workflow-test çağır
3. /workflow-build çağır
4. Production'a deploy et
```

### Agent-Generated Workflows

Agent'tan workflow **oluşturmasını** da isteyebilirsiniz. Özellikle bir dizi adımı
manüel olarak birlikte tamamladıktan sonra "bu adımları workflow olarak kaydet"
demeniz yeterlidir — agent konuşma geçmişinden workflow oluşturur.

## `@` ile Dosya Referansı (Mentions)

Kural ve workflow dosyalarında `@dosya-adı` ile başka dosyalara referans verebilirsiniz:

| Yazım                 | Çözümleme                                                               |
| --------------------- | ----------------------------------------------------------------------- |
| `@dosya.md`           | Kural dosyasının bulunduğu dizine **göreceli** olarak çözümlenir        |
| `@/path/to/dosya.md`  | Önce mutlak yol olarak denenir, bulunamazsa repo köküne göreceli denenir |

### Örnek

```markdown
---
trigger: always_on
---

Proje mimarisini @/docs/core/01.base.md dosyasından oku.
Güvenlik kurallarını @/SECURITY.md dosyasına göre uygula.
```

## En İyi Yapılandırma Yöntemleri

### 1. Katmanlı Kural Stratejisi

```
~/.gemini/GEMINI.md          → Tüm projelerde geçerli (kişisel tercihler)
.agents/rules/code-style.md  → Bu projede always_on (proje standartları)
.agents/rules/security.md    → Bu projede always_on (güvenlik kuralları)
.agents/rules/debug.md       → model_decision (gerektiğinde hata ayıklama)
.agents/rules/ts-only.md     → glob: *.ts (sadece TypeScript dosyalarında)
```

### 2. Kural Yazma İpuçları

| Yap ✅                                              | Yapma ❌                                          |
| --------------------------------------------------- | ------------------------------------------------- |
| Kuralları kısa ve net yaz                            | Tek kurala her şeyi sığdırma                       |
| Her kural dosyasına tek bir konu ver                 | Çelişen kurallar yazma                             |
| `description` alanını anlamlı yaz (model_decision)   | Description'ı boş bırakma                          |
| Dosya tipine özel kuralları `glob` ile ayır          | Global'e projeye özel kurallar koyma               |
| Gerçek proje örnekleri ekle                          | Soyut ve belirsiz talimatlar verme                 |

### 3. AGENTS.md / CLAUDE.md / GEMINI.md Kullanım Farkları

| Dosya        | Kim Okur       | Nereye Yazılır | Nasıl Yapılandırılır                                         |
| ------------ | -------------- | -------------- | ------------------------------------------------------------ |
| `GEMINI.md`  | Gemini agent   | Proje kökü     | Proje bağlamı, mimari özet, kısıtlamalar                      |
| `CLAUDE.md`  | Claude agent   | Proje kökü     | Proje bağlamı, tercih edilen çıktı formatı, yasaklar          |
| `AGENTS.md`  | Codex agent    | Proje kökü     | Proje yapısı, komutlar, commit kuralları, modül bilgileri      |

> **Öneri:** Bu üç dosyada **ortak** bilgileri (proje yapısı, dizin açıklamaları,
> build komutları) tekrarlayın — çünkü her agent sadece kendi dosyasını okur.
> Projeye özel standartları hem buralara hem `.agents/rules/` altına kopyalamak
> **tutarlılık** sağlar.

### 4. Tavsiye Edilen Kural Dosyaları

Bir güvenlik projesi için önerilen minimum kural seti:

```
.agents/rules/
├── code-style.md          # always_on — kodlama standartları
├── security-rules.md      # always_on — güvenlik kontrolleri
├── error-handling.md      # model_decision — hata ayıklama yöntemleri
├── docker-rules.md        # glob: Dockerfile* — konteyner kuralları
├── test-rules.md          # glob: **/*.test.* — test yazma kuralları
└── turkish-docs.md        # always_on — dokümantasyon dili ve formatı
```
