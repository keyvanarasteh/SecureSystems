# 05 — `.gitignore` Yapılandırması

> Git'in **izlememesi gereken** dosya ve klasörleri tanımlayan `.gitignore` dosyası.
> Kullanılan dile göre değişir — en iyi kaynak ve dil bazlı şablonlar.
>
> Yazar: Keyvan Arasteh · İstinye Üniversitesi · 2026

---

## `.gitignore` Nedir?

Git'e **"bu dosyaları takip etme"** diyen bir filtre dosyasıdır. Commit'e
dahil edilmemesi gereken her şey burada listelenir:

- Ortam değişkenleri (`.env`) — şifreler sızmasın
- Derleme çıktıları (`dist/`, `target/`) — tekrar oluşturulabilir
- Bağımlılıklar (`node_modules/`) — `npm install` ile geri gelir
- Editör dosyaları (`.idea/`) — kişisel ayarlar

---

## Mevcut Proje `.gitignore`

```gitignore
.env
```

> Şu anda sadece `.env` dosyası dışlanıyor. Proje büyüdükçe dil ve araçlara
> göre aşağıdaki kurallar eklenmeli.

---

## Dile Göre Değişir

`.gitignore` **projenin kullandığı dile göre farklılaşır**. Python projesiyle
Rust projesi aynı dosyaları üretmez:

| Dil / Araç   | Dışlanması Gereken Dosyalar                            |
| ------------ | ------------------------------------------------------ |
| **Node.js**  | `node_modules/`, `dist/`, `.next/`, `.nuxt/`           |
| **Python**   | `__pycache__/`, `*.pyc`, `.venv/`, `*.egg-info/`       |
| **Rust**     | `target/`, `Cargo.lock` (library ise)                  |
| **C / C++**  | `*.o`, `*.so`, `*.exe`, `build/`                       |
| **Java**     | `*.class`, `*.jar`, `build/`, `.gradle/`               |
| **Go**       | `bin/`, `vendor/` (go modules kullanılıyorsa)          |
| **Docker**   | Genellikle `.dockerignore` ile ayrı yönetilir          |
| **IDE'ler**  | `.idea/`, `.vscode/` (projeye özel ise commit edilir), `*.swp` |

| `C++.gitignore`          | C++                        |

### Nasıl Kullanılır?

```bash
# 1. Direkt indirme
curl -o .gitignore https://raw.githubusercontent.com/github/gitignore/main/Node.gitignore

# 2. Birden fazla dili birleştirme
curl https://raw.githubusercontent.com/github/gitignore/main/Node.gitignore > .gitignore
curl https://raw.githubusercontent.com/github/gitignore/main/Python.gitignore >> .gitignore

# 3. gitignore.io API (birden fazla dil)
curl -sL https://www.toptal.com/developers/gitignore/api/node,python,rust,docker > .gitignore
```

### Alternatif Araç: gitignore.io

## Pattern (Kalıp) Söz Dizimi

| Kalıp              | Açıklama                                              | Örnek                    |
| ------------------- | ------------------------------------------------------ | ------------------------ |
| `dosya.txt`        | Tam dosya adı eşleştirme                               | `.env`                   |
| `*.log`            | Joker karakter — tüm `.log` uzantılı dosyalar           | `error.log`, `app.log`   |
| `klasor/`          | Tüm klasörü dışla (sonundaki `/` önemli)                | `node_modules/`          |
| `**/build`         | Herhangi bir derinlikte `build` klasörü                 | `src/build`, `lib/build` |
| `!onemli.log`      | İstisna — bu dosyayı **takip et** (ünlem ile ters kural) | Dışlanan kalıptan muaf   |
| `*.py[cod]`        | Karakter grubu — `.pyc`, `.pyo`, `.pyd`                 | Python derlenmiş dosyalar |
| `#`                | Yorum satırı                                            | `# Bu bir yorumdur`      |

## `.gitignore` vs `.dockerignore`

İki farklı dosya, iki farklı amaç:

| Özellik           | `.gitignore`                    | `.dockerignore`                |
| ------------------ | ------------------------------- | ------------------------------ |
| **Kim okur?**      | Git                             | Docker                         |
| **Ne yapar?**      | Git'in izlemediği dosyalar      | Docker build'e dahil olmayan dosyalar |
| **Neden gerekli?** | Repo temizliği, güvenlik        | Image boyutunu küçültme, hız   |
| **Birbirini etkiler mi?** | Hayır — bağımsız çalışırlar | Hayır — bağımsız çalışırlar  |

> İkisinde de `.env`, `node_modules/` gibi ortak girdiler olabilir ama
> **ayrı dosyalardır** ve birbirinin yerine geçmez.

## Sık Yapılan Hatalar

| Hata                                     | Sonuç                           | Çözüm                                    |
| ---------------------------------------- | ------------------------------- | ----------------------------------------- |
| `.gitignore` oluşturmayı unutma          | `node_modules/` git'e girer     | Projeyi oluştururken **ilk iş** `.gitignore` yaz |
| Dosyayı zaten commit ettikten sonra gitignore'a ekleme | Git hâlâ izler     | `git rm --cached dosya` ile takipten çıkar |
| `.env` dosyasını commit etme             | Şifreler git geçmişinde kalır   | `detect-secrets` + pre-commit hook        |
| Her şeyi tek kalıpla dışlama (`*`)       | Gerekli dosyalar da gider       | Spesifik kalıplar kullan, `!` ile istisna ekle |
| Dile özel kuralları bilmeme              | Gereksiz dosyalar repo'ya girer | `github/gitignore` şablonlarını kullan    |

## Zaten Commit Edilmiş Dosyayı Dışlama

`.gitignore`'a eklemek **yetmez** — dosya zaten git geçmişindeyse:

```bash
# 1. Dosyayı git takibinden çıkar (diskten SİLMEZ)
git rm --cached .env

# 2. Klasörü takipten çıkar
git rm -r --cached node_modules/

# 3. Değişikliği commit et
git commit -m "chore: remove tracked files that should be gitignored"
```

> **⚠️ Dikkat:** Dosya git **geçmişinde** kalır. Gerçek bir secret sızdıysa
> `git filter-branch` veya `BFG Repo-Cleaner` ile geçmişten de silinmeli.
