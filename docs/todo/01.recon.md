## TODO Adımları

### Bölüm A — Klonlama ve İlk İnceleme

- [ ] Listeden bir repo seçin
- [ ] Repoyu klonlayın: `git clone <repo-url>`
- [ ] Kök dizin yapısını listeleyin ve dosya/klasör sayısını not edin
- [ ] `README.md` dosyasını okuyun — projenin ne yaptığını özetleyin

---

### Bölüm B — Yapılandırma Dosyaları Analizi

Aşağıdaki dosyaları **varsa** bulun, içeriğini inceleyin ve raporunuzda açıklayın:

#### Git & Versiyon Kontrolü

- [ ] `.gitignore` — hangi dosyalar dışlanmış? Neden?
- [ ] `.gitattributes` — satır sonu kuralları var mı? İkili dosya tanımları?

#### Ortam Değişkenleri

- [ ] `.env.example` veya `.env.sample` — hangi ortam değişkenleri tanımlı?
- [ ] Kaç farklı ortam destekleniyor? (development, test, production)

#### Editör & Araç Ayarları

- [ ] `.vscode/settings.json` — hangi editör ayarları tanımlı?
- [ ] `.vscode/extensions.json` — hangi eklentiler öneriliyor?
- [ ] `.editorconfig` — kod formatı kuralları neler?

#### Kod Kalitesi

- [ ] `.prettierignore` / `.prettierrc` — formatlama kuralları neler?
- [ ] `.eslintrc` / `eslint.config.*` — lint kuralları neler?
- [ ] `.shellcheckrc` — shell script linting var mı?

#### Paket Yönetimi

- [ ] `package.json` / `Cargo.toml` / `requirements.txt` — bağımlılıklar neler?
- [ ] `.npmrc` / `.yarnrc` — paket yöneticisi ayarları?
- [ ] `.npmignore` — publish dışlama kuralları?
- [ ] Lock dosyası hangisi? (`package-lock.json`, `bun.lockb`, `pnpm-lock.yaml`)

#### Docker & Konteyner

- [ ] `Dockerfile` var mı? Kaç aşamalı (multi-stage)?
- [ ] `docker-compose.yml` — hangi servisler tanımlı?
- [ ] `.dockerignore` — build context'ten neler dışlanmış?

#### Güvenlik

- [ ] `.detect-secrets.cfg` / `.secrets.baseline` — secret tarama var mı?
- [ ] `SECURITY.md` — güvenlik politikası var mı?

#### CI/CD

- [ ] `.github/workflows/` — hangi CI pipeline'ları tanımlı?
- [ ] Hangi testler otomatik çalışıyor?

#### AI Agent Yapılandırması

- [ ] `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` — AI agent talimatları var mı?
- [ ] `.agents/rules/` — hangi kurallar tanımlı?
- [ ] `.agents/workflows/` — hangi iş akışları tanımlı?

---

### Bölüm C — Giriş Noktası (Entry Point) Tespiti

- [ ] Uygulamanın **başlangıç dosyasını** bulun
  - `package.json` → `"main"` veya `"scripts.start"` alanına bakın
  - `Cargo.toml` → `[[bin]]` bölümüne bakın
  - `Dockerfile` → `CMD` veya `ENTRYPOINT` komutuna bakın
- [ ] Başlangıç dosyasından itibaren **ilk 3 seviye** çağrı zincirini çıkarın
  - `main.ts` → `createApp()` → `registerRoutes()` → ...
- [ ] Uygulama hangi portu dinliyor?
- [ ] Uygulama hangi framework'ü kullanıyor? (Express, Fastify, Axum, Flask vb.)

---

### Bölüm D — Kimlik Doğrulama & Yetkilendirme Analizi

Projede aşağıdaki sistemlerden herhangi biri **varsa** tespit edin:

#### Kimlik Doğrulama (Authentication)

- [ ] Auth sistemi var mı? (JWT, Session, OAuth, API Key vb.)
- [ ] Auth dosyalarının yollarını listeleyin (örn: `src/auth/`, `src/middleware/auth.ts`)
- [ ] Kullanılan tekniği açıklayın:
  - Token tabanlı mı? (JWT)
  - Oturum tabanlı mı? (Session + Cookie)
  - Üçüncü parti mi? (OAuth2 — Google, GitHub vb.)
- [ ] Login/Register endpoint'leri neler?

#### Middleware

- [ ] Hangi middleware'ler tanımlı? (auth, CORS, rate-limit, logging vb.)
- [ ] Middleware dosyalarının yollarını listeleyin
- [ ] Middleware sıralaması (execution order) nasıl?

#### Yetkilendirme (Authorization)

- [ ] Rol tabanlı erişim kontrolü (RBAC) var mı?
- [ ] Hangi roller tanımlı? (admin, user, moderator vb.)
- [ ] İzin (permission) sistemi nasıl çalışıyor?
- [ ] Korumalı rotaları listeleyin (hangi rotalar auth gerektiriyor?)

## Rapor Formatı

Raporunuzu **Markdown (.md)** formatında hazırlayın. Şablon:

```markdown
# Repo Keşif Raporu: [Proje Adı]

**Öğrenci:** [Ad Soyad]
**Tarih:** [Tarih]
**Repo:** [GitHub URL]

## 1. Proje Özeti
[Projenin ne yaptığı, kullandığı teknolojiler]

## 2. Dizin Yapısı
[Kök dizin ağacı ve açıklamaları]

## 3. Yapılandırma Dosyaları Analizi
[Her dosya için: bulundu mu, ne içeriyor, ne amaçla kullanılıyor]

## 4. Giriş Noktası
[Başlangıç dosyası, çağrı zinciri, framework, port]

## 5. Kimlik Doğrulama & Yetkilendirme
[Auth sistemi, middleware, roller, izinler]

## 6. Güvenlik Değerlendirmesi
[Tespit edilen güvenlik uygulamaları ve eksiklikler]

## 7. Sonuç
[Genel değerlendirme ve öneriler]
```
